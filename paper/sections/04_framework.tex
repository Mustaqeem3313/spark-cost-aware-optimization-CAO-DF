\section{The CAO-DF Decision Framework}
\label{sec:framework}

CAO-DF turns the cost model of Section~\ref{sec:problem} into a decision procedure. It is
deliberately rule-based: every decision can be traced to a measured saving, a measured one-time
cost and the expected number of executions, and no learned model is involved.

\subsection{Inputs and outputs}
The framework takes (i) the features of a workload $w$ (data volume, number of input files and
shuffle volume), (ii) the expected number of future executions $N$, and (iii) a cost table of
$\Cstatic$, $\Crun(a)$ and $\Copt(a)$ for a set of profiled reference workloads. It returns
one of three decisions: \emph{keep static}, \emph{tune} (A1, with a partition count) or
\emph{compact} (A2), together with the estimated total cost of each option and the break-even
point of each action.

\subsection{Decision rule}
Fig.~\ref{fig:algo} gives the procedure. The framework first estimates the costs of $w$ from
the cost table, then discards any action whose estimated saving is not larger than the
measurement noise floor $\delta(w)$, and finally chooses the option with the lowest total cost.
Ties are resolved in favour of the static configuration, because an action that does not
clearly save money should not be applied.

\begin{figure}[t]
\centering
\fbox{\begin{minipage}{0.94\columnwidth}
\small
\textbf{Input:} workload $w$, executions $N$, cost table $T$\\
\textbf{Output:} decision $a^{*} \in \{\textit{none}, \mathrm{A1}, \mathrm{A2}\}$
\begin{algorithmic}[1]
  \STATE $(\Cstatic, \{\Copt(a), \Crun(a)\}_{a}) \leftarrow \textsc{Estimate}(w, T)$
  \STATE $TC(\textit{none}) \leftarrow N \cdot \Cstatic$
  \FOR{$a \in \{\mathrm{A1}, \mathrm{A2}\}$}
    \IF{$\Cstatic - \Crun(a) \le \delta(w)$}
      \STATE $TC(a) \leftarrow \infty$ \COMMENT{saving within noise}
    \ELSE
      \STATE $TC(a) \leftarrow \Copt(a) + N \cdot \Crun(a)$
    \ENDIF
  \ENDFOR
  \STATE $a^{*} \leftarrow \arg\min_{a} TC(a)$, ties $\rightarrow$ \textit{none}
  \RETURN $a^{*}$
\end{algorithmic}
\end{minipage}}
\caption{The CAO-DF decision procedure.}
\label{fig:algo}
\end{figure}

\subsection{Why a noise floor is needed}
Without the noise floor the rule would act on differences that are measurement noise. Two
observations from our experiments motivate it. First, for workloads stored as a single file,
compaction rewrites data that is already compact; its measured ``saving'' is a few
milliseconds of either sign, yet a naive rule can still report a finite break-even point for
it. Second, near the optimum of A1, several partition counts are indistinguishable within
run-to-run variation, so the identity of the single fastest setting is partly an accident of
measurement. The noise floor turns both cases into explicit ties. We set $\delta(w)$ from the
run-to-run variation of the static configuration of $w$ \tbd{exact definition and value,
fixed in Phase 9 before validation}.

\subsection{Choosing the A1 setting}
For A1, \textsc{Estimate} returns the partition count with the lowest estimated per-execution
cost. Settings whose cost lies within $\delta(w)$ of the best form a plateau of equivalent
choices, and we report the plateau rather than a single value. Because P1 and P2 weight
parallelism differently, the chosen setting may depend on the cost proxy; the framework
evaluates each proxy separately.

\subsection{Unseen workloads}
A practical framework must decide for workloads it has not profiled. \textsc{Estimate}
therefore maps $w$ to the profiled reference workloads using its observable features.
